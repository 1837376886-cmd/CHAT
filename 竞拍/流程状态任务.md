# 拍卖活动状态流转 — 轻量级方案（无中间件）

## 方案选型对比

| 方案 | 精度 | 内存占用 | 复杂度 | 持久化 | 推荐 |
|------|------|---------|--------|--------|------|
| ScheduledExecutorService（1秒轮询DB） | 秒级 | 低 | 最低 | 天然持久化 | ✅ 最简单 |
| **DelayQueue（延迟队列）** | **毫秒级** | **中** | **低** | **需编码** | **✅ 最推荐** |
| HashedWheelTimer（时间轮） | 毫秒级 | 低 | 中 | 需编码 | ✅ 大量任务时 |
| 数据库1分钟轮询 | 分钟级 | 最低 | 最低 | 天然持久化 | ❌ 不精确 |

---


## 推荐方案：ScheduledThreadPoolExecutor（多线程版） 最终定版用这个方案

**核心思路**：每个活动任务独立延迟调度，线程池并发执行，互不阻塞。

### 状态流转定义

活动完整状态机（8个状态，4个自动流转节点）：

| 状态值 | 状态名 | 说明 | 进入方式 |
|--------|--------|------|---------|
| 0 | 待发布 | 第三方提交，运营未审核 | 第三方提交 |
| 1 | 待启动 | 运营审核通过，等待 publish_start_time | 运营审核通过 |
| **2** | **报名中** | 用户可以报名、缴纳保证金 | **延时任务: publish_start_time** |
| **3** | **结束报名（待竞拍）** | 报名截止，等待 auction_start_time | **延时任务: register_end_time** |
| **4** | **竞拍中** | 用户可以出价竞拍 | **延时任务: auction_start_time** |
| 5 | 已结束 | 竞拍时间到，正在判断成交/流拍 | 延时任务: auction_end_time |
| 6 | 已成交 | 有人出价，生成成交记录 | 自动判断（bid_count > 0） |
| 7 | 流拍 | 无人出价，生成退款单 | 自动判断（bid_count = 0） |

**4个延时任务触发的流转（本文档核心）**：

| 延时任务Type | 流转 | 触发时间字段 | 状态变更 | 可延时 |
|-------------|------|------------|---------|--------|
| 1 | 待启动 → 报名中 | `publish_start_time` | 1 → 2 | ❌ |
| 2 | 报名中 → 结束报名 | `register_end_time` | 2 → 3 | ❌ |
| 3 | 结束报名 → 竞拍中 | `auction_start_time` | 3 → 4 | ❌ |
| 4 | 竞拍中 → 已结束 | `actual_end_time`（默认=auction_end_time） | 4 → 5 → 6/7 | ✅ 支持多次 |

**延时竞拍规则说明**：
- 触发条件：在 `actual_end_time` 前 `delay_trigger_minutes`（默认5）分钟内有人出价
- 延时幅度：每次延长 `delay_step_minutes`（默认5）分钟
- 可触发次数：多次，无上限（只要结束前 delay_trigger_minutes 分钟内有人出价就继续延）
- 字段分离：`auction_end_time` 记录原始结束时间（不变），`actual_end_time` 记录延时后的实际结束时间（每次更新）
- 调度依据：`actual_end_time` 有值则用，否则用 `auction_end_time`
- 前端倒计时：以 `actual_end_time` 为准进行倒计时展示

### 实体与数据库设计

#### 1. StateScheduleTask 实体类

```java
/**
 * 状态流转调度任务实体
 * 每个活动发布时生成4条记录，对应4个自动流转节点：
 *   1. 待启动→报名中（publish_start_time）
 *   2. 报名中→结束报名（register_end_time）
 *   3. 结束报名→竞拍中（auction_start_time）
 *   4. 竞拍中→已结束（auction_end_time，再判断成交/流拍）
 * 服务重启时从DB恢复到内存调度器，保证任务不丢失
 */
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
@TableName("auction_state_schedule")
public class StateScheduleTask implements Delayed, Serializable {

    private static final long serialVersionUID = 1L;

    /** 主键ID */
    @TableId(type = IdType.AUTO)
    private Long id;

    /** 活动ID */
    private Long activityId;

    /**
     * 流转类型
     * 1-待启动→报名中  2-报名中→结束报名  3-结束报名→竞拍中  4-竞拍中→已结束
     */
    private Integer transitionType;

    /** 计划执行时间（精确到毫秒） */
    private Date scheduledTime;

    /**
     * 任务状态
     * 0-待执行  1-已执行  2-已取消
     */
    private Integer status;

    /** 创建时间 */
    private Date createTime;

    /** 更新时间 */
    private Date updateTime;

    // ==================== Delayed接口实现（用于DelayQueue排序） ====================

    @Override
    public long getDelay(TimeUnit unit) {
        long diff = scheduledTime.getTime() - System.currentTimeMillis();
        return unit.convert(diff, TimeUnit.MILLISECONDS);
    }

    @Override
    public int compareTo(Delayed other) {
        long diff = this.getDelay(TimeUnit.MILLISECONDS)
                     - other.getDelay(TimeUnit.MILLISECONDS);
        return Long.compare(diff, 0);
    }
}
```

### 核心调度服务

```java
@Service
@Slf4j
public class AuctionStateScheduler implements InitializingBean, DisposableBean {

    private final AuctionStateScheduleMapper scheduleMapper;
    private final AuctionActivityMapper activityMapper;
    private final AuctionBidService bidService;
    private final AuctionDealService dealService;
    private final AuctionDepositService depositService;
    private final StringRedisTemplate redisTemplate;

    /**
     * 多线程调度线程池
     * 线程数 = CPU核数 * 2（可同时处理多个活动的结束流程）
     *
     * 为什么不用单线程：
     * 50场活动同时结束，单线程串行处理最后一场延迟49秒！
     * 多线程并行处理，最后一场只延迟~1秒
     */
    private final ScheduledThreadPoolExecutor executor;

    /**
     * 保存Future引用，用于取消任务（竞拍延时场景）
     * Key = "activityId:transitionType"  Value = Future
     */
    private final ConcurrentHashMap<String, ScheduledFuture<?>> futureMap =
        new ConcurrentHashMap<>();

    public AuctionStateScheduler() {
        int poolSize = Runtime.getRuntime().availableProcessors() * 2;
        this.executor = new ScheduledThreadPoolExecutor(poolSize, r -> {
            Thread t = new Thread(r, "auction-scheduler-" + r.hashCode());
            t.setDaemon(true);
            return t;
        });
        // 取消的任务从队列中移除，防止内存泄漏
        executor.setRemoveOnCancelPolicy(true);
        log.info("[状态调度器] 线程池初始化，核心线程数: {}", poolSize);
    }

    /**
     * 服务启动：从DB恢复所有未执行的任务
     */
    @Override
    public void afterPropertiesSet() {
        List<StateScheduleTask> pendingTasks = scheduleMapper.selectByStatus(0);
        int loaded = 0, executed = 0;

        for (StateScheduleTask task : pendingTasks) {
            if (task.getScheduledTime().getTime() <= System.currentTimeMillis()) {
                // 已超期，立即执行
                executeTransition(task);
                executed++;
            } else {
                // 未到期，重新注册调度
                registerTask(task);
                loaded++;
            }
        }

        log.info("[状态调度器] 启动恢复完成：加载{}个任务，立即执行{}个超期任务",
                loaded, executed);
    }

    /**
     * 【核心】活动审核通过发布时：一次性注册全部4个流转延时任务
     * 
     * 设计说明：
     * 4个时间点（publish_start_time / register_end_time / auction_start_time / auction_end_time）
     * 在活动创建时已全部确定，因此一次性全部注册到调度器。
     * 这样即使服务重启，afterPropertiesSet会从DB恢复所有pending任务，不会断链。
     * 
     * 调用时机：运营审核通过、活动状态变更为"待启动(1)"时调用
     */
    public void registerAllTransitions(Long activityId) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null) {
            log.warn("[注册流转任务] 活动不存在: activityId={}", activityId);
            return;
        }

        long now = System.currentTimeMillis();
        int registered = 0;

        // 1. 待启动(1) → 报名中(2) — publish_start_time
        if (activity.getPublishStartTime() != null) {
            long delay = activity.getPublishStartTime().getTime() - now;
            if (delay > 0) {
                doRegister(activityId, 1, activity.getPublishStartTime());
                registered++;
            } else {
                // 已超期，立即执行
                executor.execute(() -> handlePendingToRegistering(activityId));
            }
        }

        // 2. 报名中(2) → 结束报名(3) — register_end_time
        if (activity.getRegisterEndTime() != null) {
            long delay = activity.getRegisterEndTime().getTime() - now;
            if (delay > 0) {
                doRegister(activityId, 2, activity.getRegisterEndTime());
                registered++;
            }
        }

        // 3. 结束报名(3) → 竞拍中(4) — auction_start_time
        if (activity.getAuctionStartTime() != null) {
            long delay = activity.getAuctionStartTime().getTime() - now;
            if (delay > 0) {
                doRegister(activityId, 3, activity.getAuctionStartTime());
                registered++;
            }
        }

        // 4. 竞拍中(4) → 已结束(5/6/7) — 使用 actual_end_time（有延时则用延时后的，否则用 auction_end_time）
        Date effectiveEndTime = activity.getActualEndTime() != null
                ? activity.getActualEndTime()
                : activity.getAuctionEndTime();
        if (effectiveEndTime != null) {
            long delay = effectiveEndTime.getTime() - now;
            if (delay > 0) {
                doRegister(activityId, 4, effectiveEndTime);
                registered++;
            }
        }

        log.info("[注册流转任务] activityId={}, 成功注册{}个延时任务", activityId, registered);
    }

    /**
     * 内部注册：写DB + 注册调度（供registerAllTransitions和scheduleTask使用）
     */
    private void doRegister(Long activityId, int transitionType, Date scheduledTime) {
        // 1. 先写DB持久化
        StateScheduleTask task = StateScheduleTask.builder()
                .activityId(activityId)
                .transitionType(transitionType)
                .scheduledTime(scheduledTime)
                .status(0)
                .createTime(new Date())
                .build();
        scheduleMapper.insert(task);

        // 2. 注册到调度器
        registerTask(task);
    }

    /**
     * 【对外接口】注册单个延时任务
     * 用于特殊场景（如竞拍延时重新注册结束任务）
     */
    public void scheduleTask(Long activityId, int transitionType, Date scheduledTime) {
        long delay = scheduledTime.getTime() - System.currentTimeMillis();

        // 先写DB持久化
        StateScheduleTask task = StateScheduleTask.builder()
                .activityId(activityId)
                .transitionType(transitionType)
                .scheduledTime(scheduledTime)
                .status(0)
                .createTime(new Date())
                .build();
        scheduleMapper.insert(task);

        // 注册延迟执行
        registerTask(task);
    }

    /**
     * 注册任务到线程池（内部方法）
     */
    private void registerTask(StateScheduleTask task) {
        long delay = task.getScheduledTime().getTime() - System.currentTimeMillis();
        if (delay <= 0) {
            // 已超期立即执行（提交到线程池异步执行，不阻塞当前线程）
            executor.execute(() -> executeTransition(task));
            return;
        }

        String key = task.getActivityId() + ":" + task.getTransitionType();

        // 取消旧的同类型任务（防止重复）
        ScheduledFuture<?> oldFuture = futureMap.remove(key);
        if (oldFuture != null) {
            oldFuture.cancel(false);
        }

        // 注册新的延迟任务
        ScheduledFuture<?> future = executor.schedule(
            () -> executeTransition(task),
            delay,
            TimeUnit.MILLISECONDS
        );

        futureMap.put(key, future);
    }

    /**
     * 取消任务
     */
    public void cancelTask(Long activityId, int transitionType) {
        String key = activityId + ":" + transitionType;
        ScheduledFuture<?> future = futureMap.remove(key);
        if (future != null) {
            future.cancel(false);
        }
        scheduleMapper.updateStatusByActivityAndType(activityId, transitionType, 2);
    }

    /**
     * 竞拍延时：取消旧结束任务，注册新结束任务
     * 
     * 触发条件：竞拍结束前 delay_trigger_minutes（默认5）分钟内有人出价
     * 延时规则：每次延时 delay_step_minutes（默认5）分钟
     * 可触发多次：只要每次在延时后的新结束时间前 delay_trigger_minutes 分钟内有人出价，继续延
     * 
     * 字段说明：
     * - auction_end_time：原始结束时间（不变，用于展示和历史记录）
     * - actual_end_time：实际结束时间（每次延时后更新，调度器以此为依据）
     */
    public void postponeAuctionEnd(Long activityId, Date newEndTime) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null) {
            log.warn("[竞拍延时] 活动不存在: activityId={}", activityId);
            return;
        }

        // 1. 取消旧的"竞拍中→已结束"任务（type=4）
        cancelTask(activityId, 4);

        // 2. 注册新的结束任务（新actual_end_time）
        scheduleTask(activityId, 4, newEndTime);

        // 3. 更新DB：actual_end_time（auction_end_time保持不变）
        activityMapper.updateActualEndTime(activityId, newEndTime);

        // 4. 更新Redis缓存（前端轮询感知倒计时重置）
        redisTemplate.opsForValue().set(
            "auction:actual_end:" + activityId,
            String.valueOf(newEndTime.getTime())
        );

        log.info("[竞拍延时] activityId={}, newActualEndTime={}", activityId, newEndTime);
    }

    /**
     * 执行状态流转（由线程池调度执行）
     */
    @Transactional(rollbackFor = Exception.class)
    public void executeTransition(StateScheduleTask task) {
        log.info("[状态流转] 执行: activityId={}, type={}, scheduledTime={}",
                task.getActivityId(), task.getTransitionType(), task.getScheduledTime());

        try {
            switch (task.getTransitionType()) {
                case 1: // 待启动(1) → 报名中(2)
                    handlePendingToRegistering(task.getActivityId());
                    break;
                case 2: // 报名中(2) → 结束报名/待竞拍(3)
                    handleRegisteringToPendingBid(task.getActivityId());
                    break;
                case 3: // 结束报名(3) → 竞拍中(4)
                    handlePendingBidToBidding(task.getActivityId());
                    break;
                case 4: // 竞拍中(4) → 已结束(5)，再判断成交(6)/流拍(7)
                    handleBiddingToEnded(task.getActivityId());
                    break;
            }
            task.setStatus(1); // 已执行
        } catch (Exception e) {
            log.error("[状态流转] 执行失败: taskId={}", task.getId(), e);
            // 失败不抛异常，避免影响其他任务的线程
        } finally {
            if (task.getId() != null) {
                scheduleMapper.updateStatus(task.getId(), task.getStatus());
            }
        }
    }

    /**
     * 待启动(1) → 报名中(2)
     * 触发时间: publish_start_time
     * 
     * 执行完成后：链式注册下一个任务 type=2（报名中→结束报名）
     * 兜底机制：如果发布时未注册后续任务，在这里补注册
     */
    private void handlePendingToRegistering(Long activityId) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null || activity.getStatus() != 1) {
            log.warn("[待启动→报名中] 条件不满足: activityId={}, status={}",
                    activityId, activity != null ? activity.getStatus() : "null");
            return;
        }
        activityMapper.updateStatus(activityId, 2);
        redisTemplate.opsForValue().set("auction:status:" + activityId, "2");
        log.info("[待启动→报名中] activityId={}", activityId);

        // 链式兜底：确保type=2（报名中→结束报名）已注册
        chainRegisterNext(activityId, 2, activity.getRegisterEndTime());
    }

    /**
     * 报名中(2) → 结束报名/待竞拍(3)
     * 触发时间: register_end_time
     * 
     * 执行完成后：链式注册下一个任务 type=3（结束报名→竞拍中）
     */
    private void handleRegisteringToPendingBid(Long activityId) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null || activity.getStatus() != 2) {
            log.warn("[报名中→结束报名] 条件不满足: activityId={}, status={}",
                    activityId, activity != null ? activity.getStatus() : "null");
            return;
        }
        activityMapper.updateStatus(activityId, 3);
        redisTemplate.opsForValue().set("auction:status:" + activityId, "3");
        log.info("[报名中→结束报名] activityId={}, 报名已截止", activityId);

        // 链式兜底：确保type=3（结束报名→竞拍中）已注册
        chainRegisterNext(activityId, 3, activity.getAuctionStartTime());
    }

    /**
     * 结束报名/待竞拍(3) → 竞拍中(4)
     * 触发时间: auction_start_time
     * 
     * 执行完成后：链式注册下一个任务 type=4（竞拍中→已结束）
     */
    private void handlePendingBidToBidding(Long activityId) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null || activity.getStatus() != 3) {
            log.warn("[结束报名→竞拍中] 条件不满足: activityId={}, status={}",
                    activityId, activity != null ? activity.getStatus() : "null");
            return;
        }
        activityMapper.updateStatus(activityId, 4);
        redisTemplate.opsForValue().set("auction:status:" + activityId, "4");
        log.info("[结束报名→竞拍中] activityId={}, 竞拍开始", activityId);

        // 链式兜底：确保type=4（竞拍中→已结束）已注册
        chainRegisterNext(activityId, 4, activity.getAuctionEndTime());
    }

    /**
     * 竞拍中(4) → 已结束(5)，再判断成交(6)/流拍(7)
     * 
     * 触发时间: actual_end_time（非 auction_end_time！）
     * 
     * 重要说明：
     * - 如果竞拍被延时过，auction_end_time 是原始结束时间（不变）
     * - actual_end_time 是延时后的实际结束时间（每次延时更新）
     * - 调度器注册的任务时间 = actual_end_time（或 auction_end_time 如果没延时）
     * - 此处的双重校验是最后一道保险：如果 actual_end_time 又被更新了，说明又有人出价延时
     */
    private void handleBiddingToEnded(Long activityId) {
        AuctionActivity activity = activityMapper.selectById(activityId);
        if (activity == null || activity.getStatus() != 4) {
            log.warn("[竞拍中→已结束] 条件不满足: activityId={}, status={}",
                    activityId, activity != null ? activity.getStatus() : "null");
            return;
        }

        // 双重校验：actual_end_time 是否又被更新了（再次延时）
        // 取 actual_end_time（有延时）或 auction_end_time（无延时）
        Date effectiveEndTime = activity.getActualEndTime() != null
                ? activity.getActualEndTime()
                : activity.getAuctionEndTime();

        if (effectiveEndTime != null && effectiveEndTime.after(new Date())) {
            log.info("[竞拍中→已结束] 实际结束时间还未到（可能又延时了），跳过: activityId={}, effectiveEndTime={}",
                    activityId, effectiveEndTime);
            return;
        }

        // 先更新为"已结束"状态
        activityMapper.updateStatus(activityId, 5);
        redisTemplate.opsForValue().set("auction:status:" + activityId, "5");

        // 判断是否有人出价 → 决定成交(6)还是流拍(7)
        int bidCount = bidService.getBidCount(activityId);

        if (bidCount == 0) {
            // 无人出价 → 流拍(7)
            activityMapper.updateStatus(activityId, 7);
            depositService.generateRefundOrdersForAll(activityId);
            redisTemplate.opsForValue().set("auction:status:" + activityId, "7");
            log.info("[竞拍流拍] activityId={}, 无人出价", activityId);
        } else {
            // 有人出价 → 成交(6)
            activityMapper.updateStatus(activityId, 6);
            AuctionDeal deal = dealService.createDeal(activityId);
            depositService.generateRefundOrdersForAll(activityId);
            redisTemplate.opsForValue().set("auction:status:" + activityId, "6");
            redisTemplate.opsForValue().set(
                "auction:result:" + activityId, JSON.toJSONString(deal)
            );
            log.info("[竞拍成交] activityId={}, dealId={}", activityId, deal.getId());
        }
        // 状态4是最后一个自动流转节点，无需链式注册下一个
    }

    /**
     * 链式兜底：检查并注册下一个流转任务
     * 
     * 设计说明：
     * 主机制是活动发布时一次性注册全部4个任务（registerAllTransitions）。
     * 此方法作为兜底保险：如果主机制漏注册了某个任务，
     * 在当前任务执行时自动补注册下一个任务，确保状态机不会卡住。
     * 
     * 场景举例：
     * - 发布时只注册了type=1，type=2漏了
     * - type=1执行完 → 检查发现DB中没有type=2的pending任务 → 自动补注册
     * 
     * @param activityId      活动ID
     * @param nextType        下一个流转类型
     * @param nextScheduledTime 下一个计划执行时间
     */
    private void chainRegisterNext(Long activityId, int nextType, Date nextScheduledTime) {
        if (nextScheduledTime == null) return;

        // 检查是否已存在pending的下一个任务
        StateScheduleTask exist = scheduleMapper.selectPending(activityId, nextType);
        if (exist != null) {
            return; // 已存在，无需重复注册
        }

        // 不存在则补注册
        long delay = nextScheduledTime.getTime() - System.currentTimeMillis();
        if (delay > 0) {
            doRegister(activityId, nextType, nextScheduledTime);
            log.info("[链式兜底] 补注册下一个任务: activityId={}, type={}, scheduledTime={}",
                    activityId, nextType, nextScheduledTime);
        }
    }

    @Override
    public void destroy() {
        executor.shutdownNow();
        log.info("[状态调度器] 已关闭");
    }
}
```

## 单线程 vs 多线程对比

| 指标 | DelayQueue单线程 | ScheduledThreadPoolExecutor多线程 |
|------|-----------------|-----------------------------------|
| 并发处理 | ❌ 串行，互相阻塞 | ✅ 并行，互不阻塞 |
| 50场同时结束 | 最后一场延迟49秒 | 最后一场延迟~1秒 |
| 任务取消 | O(n)遍历队列 | O(1)Future.cancel |
| 实现复杂度 | 需自管消费线程 | JDK原生，开箱即用 |
| **推荐度** | ❌ 不推荐用于生产 | ✅ **强烈推荐** |
## 备选：DelayQueue（了解即可，不推荐）

如果活动数量不多（<1000场并发），可以用JDK自带的调度线程池，代码更简单：

```java
@Service
@Slf4j
public class AuctionStateSchedulerV2 implements InitializingBean, DisposableBean {

    private final AuctionStateScheduleMapper scheduleMapper;
    private final ScheduledThreadPoolExecutor executor;

    // 线程数 = CPU核数 * 2
    public AuctionStateSchedulerV2() {
        this.executor = new ScheduledThreadPoolExecutor(
            Runtime.getRuntime().availableProcessors() * 2,
            r -> {
                Thread t = new Thread(r, "auction-scheduler");
                t.setDaemon(true);
                return t;
            }
        );
        // 取消的任务从队列移除
        executor.setRemoveOnCancelPolicy(true);
    }

    /**
     * 注册任务
     */
    public void scheduleTask(Long activityId, int type, Date scheduledTime) {
        long delay = scheduledTime.getTime() - System.currentTimeMillis();
        if (delay <= 0) {
            // 已超期，立即执行
            executeNow(activityId, type);
            return;
        }

        // 先写DB
        StateScheduleTask task = new StateScheduleTask();
        task.setActivityId(activityId);
        task.setTransitionType(type);
        task.setScheduledTime(scheduledTime);
        task.setStatus(0);
        scheduleMapper.insert(task);

        // 注册延迟执行
        ScheduledFuture<?> future = executor.schedule(
            () -> executeTransition(task),
            delay,
            TimeUnit.MILLISECONDS
        );

        // 保存future引用以便取消
        futureMap.put(task.getId(), future);
    }

    /**
     * 取消任务
     */
    public void cancelTask(Long taskId) {
        ScheduledFuture<?> future = futureMap.remove(taskId);
        if (future != null) {
            future.cancel(false); // 不中断正在执行的任务
        }
        scheduleMapper.updateStatus(taskId, 2);
    }

    /**
     * 竞拍延时：取消旧的"竞拍中→已结束"任务（type=4），注册新任务
     */
    public void postponeAuctionEnd(Long activityId, Date newEndTime) {
        // 1. 取消旧的竞拍结束任务（type=4）
        StateScheduleTask oldTask = scheduleMapper.selectPending(activityId, 4);
        if (oldTask != null) {
            cancelTask(oldTask.getId());
        }
        // 2. 注册新的结束任务
        scheduleTask(activityId, 4, newEndTime);
    }

    @Override
    public void destroy() {
        executor.shutdownNow();
    }
}
```

## 两个方案对比

| 特性 | DelayQueue | ScheduledThreadPoolExecutor |
|------|-----------|----------------------------|
| **精度** | 毫秒级 | 毫秒级 |
| **取消任务** | O(n)遍历 | O(1)直接cancel |
| **任务数量** | 适合千级 | 适合万级 |
| **CPU占用** | 阻塞等待，零CPU | 阻塞等待，零CPU |
| **代码复杂度** | 稍复杂 | 最简单 |
| **线程模型** | 单线程消费 | 线程池并发执行 |
| **推荐场景** | 任务数<5000 | 任务数<1000 |

## 最终推荐

```
如果你要最简单：ScheduledThreadPoolExecutor（20行核心代码）
如果你要最高效：DelayQueue（Netty也用类似的）
如果你任务极多（10万+）：考虑时间轮算法
```

**共同点（三层防护依然成立）**：
1. **内存精确调度**：DelayQueue / ScheduledExecutor，秒级甚至毫秒级
2. **数据库持久化**：服务重启后从DB恢复任务
3. **HTTP轮询实时校验**：出价前查Redis/DB状态，兜底防错
4. **定时任务兜底**：可选，每5分钟扫一次DB补漏（甚至可以不要这一层）

**依赖只有**：JDK + MySQL，零中间件。
